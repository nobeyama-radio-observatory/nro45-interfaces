# nro45-interfaces

国立天文台 野辺山宇宙電波観測所の 45m 鏡の観測系の、部品のあいだのインターフェース仕様です。部品は、観測指示書の作成、COSMOS、各装置、観測時系列データ、観測生データ、保管、解析です。

- **公開の情報だけを置きます。** 非公開の部分は写さず、既存の非公開の文書を「文書名、版、ページ」で引用します。
- **ここが仕様の正本です。** 形式、欄、型、単位、範囲、エラーの扱いを書きます。
- **運用の事情は書きません。** どの部品が運用中か、誰が保守しているか、境界の一覧と欠けは、運用リポジトリにあります。
  - 境界の一覧：[nro-45m-control の docs/interfaces.md](https://github.com/nobeyama-radio-observatory/nro-45m-control/blob/main/docs/interfaces.md)
  - データ経路の運用の規則：nro-data の [docs/data-path.md](https://github.com/nobeyama-radio-observatory/nro-data/blob/main/docs/data-path.md)

この構成は、文脈基盤のハブの判断記録 [0013](https://github.com/nobeyama-radio-observatory/nro-context/blob/main/decisions/0013-観測系のインターフェース仕様をnro45-interfacesにまとめる.md) で決めました。

## インターフェース

インターフェースごとにディレクトリを一つ置きます。版の一覧は、各ディレクトリの README.md にあります。ディレクトリは、最初の版の案を書くときに作ります。

| ディレクトリ | 名前 | 書く部品 → 読む部品 | 状態 |
|---|---|---|---|
| [`observation-script/`](observation-script/README.md) | 観測指示書 | 観測指示書の作成ソフト（いまは nobs）→ COSMOS のマネージャー | v1 の案 |
| `timeseries/` | 観測時系列データ | 各装置の Local Controller → quick look、マージ | 準備中 |
| `raw-data/` | 観測生データ | マージ → 保管、解析ソフト | 準備中 |
| `delivery/` | 保管と配信の形式 | 保管 → 観測者 | 準備中 |
| （置かない） | マネージャーと Local Controller の通信 | マネージャー ↔ 各装置の Local Controller | 非公開。所在は境界の一覧に書く |

- 観測指示書は、作成ソフトの出力とマネージャーの入力が同じファイルなので、インターフェースを一つにまとめています。
- マージの入力は観測時系列データ、出力は観測生データです。マージについては、この二つの仕様に書きます。

## 版の決まり

- **名前は、実装ではなく役割で付けます。** たとえば「ロギング」ではなく「観測時系列データ」とします。実装の名前は、版の別名として書きます。
- **版はインターフェースごとに独立に上げます。** リポジトリ全体の版は付けません。
- **版の上げ方：**

  | 変更 | 扱い |
  |---|---|
  | 互換性のない変更（欄の削除、意味や単位の変更） | 新しい版のファイル（`v2.md` など）を作る。古い版は「置換済み」にして残し、消さない |
  | 互換性のある追加（欄の追加） | 同じ版のファイルを書き換え、変更の履歴の節に残す |
  | 誤りの訂正 | 同じ版のファイルを書き換える |

- **状態：** 案、現行、置換済み、廃止のどれかです。
- **適用の期間：** 版ごとに、どの観測からどの観測までに使われたかを書きます。データを手にした人が、どの版の仕様で読めばよいかを引けるようにするためです。
- **データの版の印：** データのファイルの中に形式の版を示す欄があるかを、版ごとに書きます。
- **タグ：** 版が「現行」になったら、`<ディレクトリ>-v<版>`（例：`timeseries-v1`）のタグを付けます。

## 公開の範囲

次のものは書きません。

- 制御の手順、装置のあいだの通信、安全のインターロック、接続先、認証、ネットワーク構成
- 計算機の上のパスやホスト名（例とテストケースからも除く）
- 観測者 ID、プロジェクト名、占有期間中の天体や観測計画。例とテストケースは、確かめてから入れる。だめなら合成した例にする

nobs と COSMOS のソースは公開しませんが、AI が解析して要約した形式は公開してよいことになっています（nro-45m-control の[聞き取り 2026-11-19](https://github.com/nobeyama-radio-observatory/nro-45m-control/blob/main/interviews/2026-11-19.md) 問1、問5）。ソースの断片は写しません。

迷ったら入れずに、issue で相談してください。

## 書き方

- 新しいインターフェースや版は、[TEMPLATE/](TEMPLATE/) の雛形から作ります。
- 事実には出典を添えます。出典を示せない事柄は「（仮説）」とし、記録がないことは「記録がない」と書きます（ハブの判断記録 [0004](https://github.com/nobeyama-radio-observatory/nro-context/blob/main/decisions/0004-事実の根拠は出典で示す.md)）。
- 進め方の決まりの正本は、ハブの [CONTRIBUTING.md](https://github.com/nobeyama-radio-observatory/nro-context/blob/main/CONTRIBUTING.md) です。主ブランチに直接書き込まず、プルリクエストを出します。AI が作ったものにはラベル `AI作成` を付けます。
